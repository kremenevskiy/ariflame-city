# fcg — игровой сервер Флейм-Сити

Онлайн для клиента `client/`: игроки видят друг друга в реальном времени, сохранения, недвижимость и бизнесы, гонки и
режимы, уровни, рейтинги, кланы, война за районы, фоторежим и календарь недели. FastAPI + WebSocket, **своя SQLite**
(одна файловая база, WAL) — внешних баз и очередей нет. Протокол и коды закрытия — шапка `app.py`.

## Запуск

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r server/requirements.txt -r server/requirements-dev.txt
cd server && uvicorn app:app --host 127.0.0.1 --port 8091 --ws websockets --ws-max-size 8192
```

Клиент для разработки — `npm run dev` в корне (статика `client/` на :8080 и прокси `/g/*` → :8091).
Выкладка (systemd/Docker, обратный прокси, WebSocket, размер тела `/g/photo`) — [docs/DEPLOY.md](../docs/DEPLOY.md).
Лимиты «с одного адреса» (кадры фоторежима, правки с сайта) берут адрес клиента у uvicorn (`clientip.py`): за прокси
uvicorn запускают с `--proxy-headers --forwarded-allow-ips=<адрес своего прокси>` — не `*`, со `*` uvicorn берёт левый
X-Forwarded-For, а его пишет сам клиент.

| переменная | по умолчанию | что |
|---|---|---|
| `FC_DB` | `server/data/game.db` | файл SQLite (папка создаётся сама); рядом — `photos/` и `admin.key` |
| `FC_WORLD` | пусто | вебхук личности — см. «Личность»: пусто — только гости; `fake` — тесты и локально; URL — внешний сервис |
| `FC_WORLD_UA` | `FlameCity-GameServer/1.0` | User-Agent запросов к вебхуку (CDN часто режут `python-httpx/…`) |
| `FC_ORIGINS` | `*` | откуда пускать браузер (Origin) к HTTP и сокету, через запятую. Вход — токеном в теле, не кукой, поэтому `*` безопасен; в проде лучше свой адрес |
| `FC_MAX_CONN` | `300` | соединений одновременно (дальше — код 1013, клиент переподключится с паузой) |
| `FC_PHOTOS` | `<папка базы>/photos` | кадры фоторежима (живут 48 ч) |

| `FC_SITE` | `https://city.ariflame.com` | адрес сайта в письмах авторам правок (ссылки на игру и статус правки) |

## Личность

`verify(token) → rid | None` — одна функция на все ручки и сокет:

- **`FC_WORLD` не задан** (по умолчанию) — вход не настроен, все игроки — гости `g-…` (id из клиента). Гости играют
  онлайн и видят друг друга, но сохранения на сервере, недвижимость, кланы и рейтинги — только для вошедших.
- **`FC_WORLD=fake`** — для тестов и локальной проверки: токен `tok-<8 hex>` = rid. Клиент на localhost берёт его из
  `?devtok=tok-aaaa0001`.
- **`FC_WORLD=https://id.example.org`** — вебхук: сервер один раз шлёт `POST {FC_WORLD}/w/me` с телом `{"token": "<токен
  клиента>"}` и ждёт `200 {"rid": "<8–32 hex>"}` (остальные поля игнорируются); любой другой ответ — токен не принят,
  игрок — гость. Ответ кэшируется на 10 минут. Ключей и паролей у игрового сервера нет — токен проверяет тот, кто его
  выдал. Клиентская часть (как получить токен) — [docs/AUTH.md](../docs/AUTH.md). Чтобы поток случайных токенов не
  превращался в поток к сервису аккаунтов: отказ (4xx или 200 без rid) помним 60 с, один токен в полёте — один запрос,
  одновременно — до 16, всего — до 20 проверок в секунду со всплеском 400 (`WORLD_*` в `app.py`); сбой сети и 5xx не
  запоминаются.

Наружу уходят только номер соединения, ник (свой — см. «Ник» ниже, нет своего — из «Рейтинга», «Слово-NN»), код облика
и непрозрачный `fid`. rid другим игрокам не отдаётся никогда (он связал бы игрока с его домом на карте). Свободного
текста в онлайне почти нет: эмоции — номер из списка `EMO`; ник и чат клана (готовые фразы и короткий текст) — через
фильтр `crews.clean`.

Лимиты: 300 соединений (считаются с accept: сокет без `hi` тоже занимает место, `hi` ждём 5 с — дальше 4002),
20 сообщений/с (всплеск 40, 60 нарушений — отключение 4008), 1 КБ на сообщение (кадр больше 4 КБ — сразу 1009; uvicorn
принимает кадр целиком до `--ws-max-size`, по умолчанию 16 МБ — в выкладке ставить `--ws-max-size 8192`), 30 с тишины —
отключение (клиент шлёт состояние раз в секунду даже стоя), координаты по городу (`CITY_LIM`), ≤ 6 скачков за 10 с (вход
в здание не в счёт), сохранение ≤ 64 КБ и не чаще раза в 10 с. Вторая вкладка того же игрока закрывает первую (код 4000).

## Ручки

Базовые: `GET /g/health`, `/g/stats`, `/g/top`; `POST /g/save {token, save, creature?}`, `/g/load {token}`; сокет `/g/ws`.

### Ник — `nicks.py`

Игрок (гость и вошедший) называет себя сам — по сокету: `{t:"nick", nick}` → `{t:"nick", ok, nick}` или `{ok: false, why,
wait?}`; соседи получают ник в `meta` (`name`; у вошедшего он же в `pn`), «Онлайн», друзья, комнаты, рейтинги, клан и
таблицы гонок показывают его вместо «Гость»/ника из «Рейтинга». `hi.nick` — копия с устройства: заполняет пустую запись
(после той же проверки), записанный ник главнее; `welcome.name` — что записано. Таблица `nicks` по rid: вошедшему — на
любом устройстве, гостю — по его id `g-…` (записи гостей без смен 60 дней стираются).

Проверка — только сервер: NFKC, пробелы схлопнуты и обрезаны, 2–20 знаков, буквы (кириллица, латиница), цифры, пробел,
`_-.`, хотя бы одна буква; без ссылок, `@` и телефонов; занятые игрой имена (`RESERVED`, `STAFF`: Макс, Патруль, Щит,
админ, модератор, имя проекта) — без учёта регистра, похожих латинских букв и транслита; мат и политика — фильтр чата
клана `crews.clean`. Смена — не чаще раза в 30 с и не больше 10 в сутки; тот же ник ещё раз — не смена. Одинаковые ники
разрешены.

### Недвижимость, бизнесы, «Передел» — `realty.py`, `season.py`, старые ручки `homes.py`

**Здание** — `(city, key)`: Флейм-Сити — номер здания плана (`"123"`), Минск — `"m<x>_<z>"`, центр вершин контура OSM
(номера контуров меняются при пересборке `client/minsk/`, место — нет). Сервер помнит адрес, x/z, дверь, площадь, этажи,
район. Цена — формулой сервера `price_of` (та же в `client/fprop.js`). Лимит — 3 дома + 3 нежилых в каждом городе.
Продажа — 70% цены + половина вложенного в бизнес + касса.

**Бизнес** — в своём нежилом здании: 12 видов, уровни 1–5. Касса и сырьё — ленивая симуляция по часам сервера; налог
5%, зарплаты — за часы работы. Сотрудники — ИИ-агенты: кандидатов выдаёт сервер (детерминированно — подделать навык
нельзя), черты влияют на выработку, ставку, мораль, уходы. Деньги от сервера (касса, доставка, продажа) — **кредит
честности** `modes.credit`: прирост «заработано» на эту сумму не считается читом. Покупки за наличные (здание,
оборудование, улучшение и сырьё «наличными», премия, управляющий, клан и общак) клиент списывает сам — сервер пишет их
**долгом** `modes.debit` и гасит его тратами, которые видны в сохранениях (заработано выросло больше, чем деньги на руках
и в банке). Непогашенный долг съедает кредит на ту же сумму: «купил, не заплатив → продал» денег не даёт (аудит H-2).

**«Передел»** — банды игроков, неделя (UTC, понедельник); влияние от кассы, доставок и дел; итоги — лениво при первом
запросе новой недели; хозяину района +10% к кассе бизнесов банды. Призы — только игровые.

| ручка | что |
|---|---|
| `GET /g/props?city=` | занятые здания города `[{k, cls, kind, cre, x, z, biz?, lvl?, name?}]` — без rid и имени, кэш 15 с |

### Режимы и честность — `modes.py`

| что | как |
|---|---|
| трассы | `client/tracks.json` — один файл клиенту и серверу. Генератор `node tools/gen_tracks.cjs` (по улицам плана), `--check` — не отстал ли. Поменяли сетку улиц в `client/fmap.js` — перегенерировать |
| время гонки | от старта до последнего чекпоинта — часы сервера. Дисквалификация: вышел из машины, телепорт, скорость выше физической, дольше 15 мин. Гости едут, но в таблицу не попадают |
| честность денег | `/g/save`: прирост `stats.earned` ≤ бюджета по минутам игры + кредита (за вычетом непогашенного долга за покупки); нарушение — сохранение не пишется, ответ `{ok:false, rolled:true, save: <последнее честное>}`; `honest.cheat += 1`, при ≥ 3 игрока нет в топе и таблицах |
| коп против вора, налёт вместе | комнаты до 8 (налёт до 4) игроков поблизости, всё решает сервер |
| кто онлайн, друзья | `who` — координаты огрублены до 20 м; `locate` («📍 К нему») — точно и со зданием только другу, остальным — та же клетка 20 м без здания; дружба взаимная (`friends`/`friend_req`); наружу — номер соединения и `fid` |

`GET /g/races` (таблицы, трасса недели, прошлая тройка), `GET /g/districts` (рейтинг районов).

**Гонка недели.** Сервер призов не выдаёт: по итогам недели тройка пишется в `weekly_winners`. Оператор смотрит её
ручкой `GET /g/admin/winners?weeks=2` с заголовком `X-Admin-Key: <ключ>` (ключ — `FC_ADMIN_KEY` или файл `admin.key`
рядом с базой; не публикуйте его) и награждает как решит (в игре — только игровые призы).

### Уровни, рейтинги, кланы, война за районы — `progress.py`, `crews.py`, `war.py`

**Опыт выдаёт сервер**: клиент говорит только, что сделал (`{источник: сколько раз}`), сервер знает цену, режет частоту
и дневные потолки (общий — 15 000). Кривая GTA-подобная: до уровня L нужно 250·(L−1) + 60·(L−1)².

| ручка | что |
|---|---|
| `POST /g/prog/sync {token, city, gains, ach}` | опыт и новые достижения; не чаще раза в 15 с |
| `POST /g/prog/me` · `/g/prog/daily` · `/g/prog/title` · `/g/prog/nick` | профиль и места · награда за вход · титул · ник (слово из списка + число) |
| `GET /g/profile?fid=` · `GET /g/ranks?board=&scope=&city=&n=` · `GET /g/ach/stats` | карточка игрока · рейтинги (level, worth, biz, infl, race, crew × week/all × flame/minsk/all) · доли достижений |
| `GET /g/crews?q=` · `GET /g/crew?id=` · `POST /g/crew/me` | кланы · клан · свой клан |
| `POST /g/crew/create` · `/join` · `/leave` · `/disband` · `/invite` · `/answer` · `/decide` · `/role` · `/kick` · `/edit` | жизнь клана |

Правки без GitHub (contrib.py; страница `contribute.html`, PR открывает `.github/workflows/contrib-intake.yml`):

| ручка | что |
|---|---|
| `POST /g/contrib` | `{title, idea, author?, contact?, email?, tool?, agree: true}` и правка — `patch` (git diff), `files` [{path, content}] или `zip` (base64). Только текстовые файлы в `client/` и `docs/`, без удаления файлов. 200 `{id, status, files, notify}` / 400 что не так / 413 / 429 / 507 |
| `GET /g/contrib/<id>` | статус: `pending` → `taken` → `pr` (`pr_url`) → `merged` → `live`; или `rejected` / `closed` (`reason`); без автора, контакта и почты |
| `GET /g/contrib/pending`, `GET /g/contrib/watch`, `POST /g/contrib/<id>/result` | только с заголовком `X-Contrib-Key` = `FC_CONTRIB_KEY` (нет ключа — 404). `watch` — правки в `pr`/`merged`: `{id, title, status, pr_url, updated}` для сверки с GitHub |
| `GET /g/admin/contrib/outbox` | `X-Admin-Key`: письма на отправку `[{mid, cid, status, to, subject, text, html, created}]` (до 50, старые первыми) |
| `POST /g/admin/contrib/outbox/<mid>/sent` | `X-Admin-Key`, `{result: sent\|bounced}` → `{ok, erased}`; повтор — `{ok, already}` |

Статусы правки: `pending` (в очереди) → `taken` (робот забрал) → `pr` (открыт PR) → `merged` (влит в `main`) → `live` (коммит
слияния уже в выпуске `live` — в городе у всех); `rejected` — не наложилась или сторож против, `closed` — PR закрыт без
слияния (причина — последний комментарий мейнтейнера). `live`, `rejected`, `closed` — окончательные; из `pr` назад в
очередь не вернуть (иначе сбой сети после открытия PR открыл бы второй). Недопустимый переход — 409. `merged`/`live`/
`closed` сообщает тот же contrib-intake: раз в 15 минут сверяет правки из `watch` с GitHub.

**Письма авторам** (contribmail.py). Почта необязательна: строго латиницей, ≤ 120 знаков, хранится строчными. Лежит
только в базе (`contrib_mail`), не в JSON очереди — тот целиком уходит в GitHub Actions, поэтому адрес не может попасть ни
в PR, ни в журнал Actions, ни в публичные ручки. При переходе в `pr`, `merged`, `live`, `rejected`, `closed` письмо (тема,
текст и простой HTML, по-русски, на «ты») ложится в `contrib_outbox` — одно на статус, повтор отчёта не дублирует.
Отправляет их с хоста `tools/deploy/city-mail.sh` через Resend (у контейнера игры нет интернета) — [docs/DEPLOY.md](../docs/DEPLOY.md).
Адрес стирается у каждого письма сразу после отправки, а у правки — после письма об окончательном статусе или если
адрес не принимает почту (`bounced`). Неотправленное за 14 дней письмо выбрасывается, адрес правки без окончательного
статуса живёт не дольше 180 дней. Чужую почту не завалить: на один адрес — до 5 правок с письмами в сутки (дальше правка
принимается без писем, `notify: false`), ссылки из названия и ника в письмо не попадают.

Ошибки у игроков (errors.py; клиент — `client/ferr.js`) и необработанные исключения самого сервера (вид `server`):

| ручка | что |
|---|---|
| `POST /g/err` | `{sid, items: [{kind, msg, stack?, src?, line?, at?, n?, ctx?}]}`, ≤ 32 КБ и ≤ 20 штук. 204 / 400 / 413 / 429 (60 событий в час на сеанс, 20 000 в сутки всего) |
| `GET /g/admin/errors?hours=24&limit=100&kind=` | `X-Admin-Key`: сводка по отпечаткам (вид + сообщение без чисел + место в коде) — сколько раз, сколько сеансов, версии, устройства |
| `GET /g/admin/errors/<fp>` | `X-Admin-Key`: последний пример целиком и последние события этого отпечатка |
| `POST /g/report` | «Сообщить о проблеме» (`client/freport.js`: пауза, телефон, F8): `{sid, data, shot?}` — текст игрока, место, что держит рядом, сеть, кадры/с, журнал, снимок JPEG ≤ 96 КБ base64. 200 `{code: "R-7K2F"}` / 400 / 413 / 429 (6 в час на сеанс) |
| `GET /g/admin/reports`, `/g/admin/reports/<code>`, `/g/admin/reports/<code>.jpg` | `X-Admin-Key`: последние обращения, одно целиком, его снимок. Хранятся последние 3000 (снимки — `FC_REPORTS`, по умолчанию `reports/` рядом с базой) |

| `POST /g/admin/announce` | `X-Admin-Key`, `{v, in, server}`: всем в онлайне — «новая правка, перезагрузка через N с» (зовёт `tools/deploy/pull-live.sh`) |

В отчётах нет ни аккаунтов, ни ников, ни токенов: версия, город, качество графики, устройство, браузер, экран, режим
игрока и позиция с шагом 50 м.

Перед сервером нужен прокси, который пропускает тело `/g/photo` до 2 МБ (общий потолок остальных `/g/*` — 128 КБ
достаточно) — [docs/DEPLOY.md](../docs/DEPLOY.md).

## Схема

Всё в одной SQLite, `CREATE … IF NOT EXISTS` при старте, старые таблицы не меняются (миграции идемпотентны):
`players`, `sessions` (app.py); `nicks` (nicks.py); `honest`, `credit`, `races`, `weekly_winners`, `friends`, `friend_req`, … (modes.py);
`props`, `biz`, `season_*` (realty.py, season.py), `homes` (зеркало для старых клиентов); `prog*`, `biz_week`,
`biz_total`, `infl_me`, `ach` (progress.py); `crews`, `crew_*` (crews.py); `war_*` (war.py); `err_*` (errors.py);
`contrib_mail`, `contrib_outbox` (contribmail.py — почта авторов правок и письма; сами правки — папка `contrib/`).
Резервная копия — `sqlite3 game.db ".backup game-$(date +%F).db"` (безопасно на живой базе в WAL).

## Тесты

```bash
python -m pytest server/tests -q          # или npm test
```

Без сети: личность — `FC_WORLD=fake` (вебхук в `test_identity.py` подменён `httpx.MockTransport`), база — файл во
временной папке.

## Локально с входом

```bash
cd server && FC_WORLD=fake FC_DB=/tmp/fcg.db uvicorn app:app --port 8091
npm run dev     # → http://localhost:8080/?devtok=tok-aaaa0001
```

`devtok` работает только на localhost: клиент берёт rid `aaaa0001` из токена, сервер с `FC_WORLD=fake` принимает его же —
так проверяются покупка зданий, бизнесы, кланы и «Передел» целиком.
